# FEAT-02: フィーチャーフィールド連動シンボル・ラベル変更処理

環境設定およびUI属性の変更に連動した、QGISキャンバス上のシンボルとラベルのリアクティブな制御制約を定義する。

## 1. シンボロジの同期ライフサイクル
* **環境設定（グローバル）**: 設定ダイアログで設定適用時、設定永続化後に設定変更イベントを発火しレンダラーを再構築。
* **UI操作（リアクティブ）**: 色選択や属性の変更がリアルタイムコミットによってデータストアに書き込まれると、描画エンジンが自動的に再描画する。
* **フィルター表示（非表示制御）**: フィルタ条件から複数条件の評価式 (配列ベース) を生成し、動的プロパティを使ってレンダラー全体に適用し、対象外を非表示（不透明度0）とする。

## 2. 破壊不可制約 & ビジネスルール (Invariants)
* **【データ定義プロパティの利用】**: ラベル色や透過度などを反映する際、フィーチャを個別の反復処理で設定してはならない。必ずデータ定義プロパティを用い、エンジン側に式評価させること。
* **【フィルタのラベル非表示連動】**: 対象外の打刻点シンボルだけでなく、ラベルの文字や白枠バッファ（QgsPalLayerSettings）の不透明度に対しても同一の非表示式 (不透明度0) を同期して設定し、全体が完全に非表示となるようにすること。
* **【レンダラー再構築時のフィルタ設定保護】**: シンボロジ全体設定の再構築によってレンダラーが初期化されると非表示式が消失するため、再構築直後に必ずフィルタの有効状態を評価し非表示式を再注入すること。また、セッション再開時にも強制初期化を行い、前回状態の残存を防ぎ100%不透明に同期・リセットすること。
* **【イベント駆動型透過度同期】**: 透過度の再適用は「ダイアログを閉じた時」ではなく、画像削除やリネームなど属性に影響を与える処理が成功した直後に発火させるイベント駆動型で実行すること。
* **【属性による個別カラー制御の排他】**: 出土形態が特定の条件を満たす場合は全体設定のグローバル色が強制されるため、個別色選択UI要素は強制無効化しなければならない。
* **【過去遡及一括更新】**: 特定のカラーを変更した際は、同一属性を持つ過去の全ポイントのデータも遡及して一括更新される。
* **【打刻点のカテゴリ別シンボル形状】**: `S` = 丸、`P` = ダイヤ、`C` = 三角、`SP` = 二重丸の形状ルールを適用する。
* **【色と塗りつぶしルール】**: `excavation_type` が「グリッド」の場合はグローバル設定色を使用し、それ以外（遺構等）の場合は各フィーチャ属性の `color_code` をデータ定義オーバーライドで使用する。
* **【基準点のスケール依存表示】**: 小グリッドが '00' のものは `scale_major_grid`、それ以外は `scale_minor_grid` のプロパティを利用し、スケールごとの表示/非表示の閾値制御を行う。

## UI/UX ライフサイクル制約

#### 4.2 環境設定ダイアログ [SET]
* **対象**: 環境設定UI
* **配置場所**: 設定UI構築モジュール
* 🔗 **対応機能アーキテクチャ**: `FEAT-02: SYMBOLOGY_LABEL_SYNC`

##### 1. 配置UI要素 (Data & State Bindings)
* **カラーピッカー**: 各種要素の色設定UI。
* **スケール閾値設定**: スケール表示モード (常時表示 vs 指定スケール)。

##### 2. 状態・排他制御ルール
* **Stage 2 起動時からの完全な状態復元 (UX視点)**: UIの初期ステート（選択状態や入力欄の活性/非活性）はハードコードされた初期値を持たず、起動時に読み込んだ永続化データから逆算・推論され、完全な単一方向データフローで前回終了時の状態が齟齬なく復元されます。
* **指定モード連動**: スケール表示が特定の指定モードに設定された場合のみ、閾値を入力する入力要素が活性化(有効化)される。
* **変更の適用 (Apply)**: 適用アクション実行時、全入力値を収集して設定ファイルに保存する。このファイル保存完了をトリガーに発火する設定変更イベントを受け取り、キャンバス上の全シンボロジを動的（リアクティブ）に再構築・再描画する（再起動不要）。
